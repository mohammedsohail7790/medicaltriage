# Job runbooks

Generated by `pnpm runbooks:generate` from `src/services/jobRunbooks.ts`. Every job the scheduler or the integration queue can run has an entry; a test fails if one is missing. For any failure, first read the failure reason and likely cause in the alert, then the run's trace.

## Demonstration wait (`demo.wait`)

Waits for a set time. Used to try the scheduler and to prove asynchronous work.

- **Safe to run again:** yes
- **Who can correct it:** Administrator
- **When it fails:**
  - It cannot fail on its own. A run that shows cancelled was stopped by an administrator.

## Integrity checks (`integrity.check`)

Runs the six data integrity checks: audit chain, encrypted values, completed cases, deletions, stale locks and archive handoff.

- **Safe to run again:** yes
- **Who can correct it:** Security owner and administrator
- **When it fails:**
  - Open Admin, Integrity checks and read which check failed and the references it lists.
  - A broken audit chain is a security incident: follow the incident response plan before repairing anything.
  - A stale-lock problem repairs itself on the next run; the others need the named record corrected.

## Retention preview (`retention.dry_run`)

Counts what each approved retention policy would remove, without removing anything.

- **Safe to run again:** yes
- **Who can correct it:** Administrator
- **When it fails:**
  - Check the database is reachable and the retention policies exist under Admin, Retention.

## Performance check (`performance.check`)

Compares request latency, error rate and event-loop lag with the thresholds and raises a performance.degraded event when one is outside.

- **Safe to run again:** yes
- **Who can correct it:** Administrator
- **When it fails:**
  - A failure means the check itself could not run: see the error and the trace. A degradation is delivered as an alert, not as a failed run.

## Synthetic transactions (`synthetic.check`)

Runs the critical flows (clinical content search, note compilation, referral PDF, database) with invented data.

- **Safe to run again:** yes
- **Who can correct it:** Engineer on call
- **When it fails:**
  - The error names the flow that failed. Reproduce it in the cockpit with a test case.
  - A content failure usually means the clinical content package did not load: check the content release and the service logs.

## Metrics report by email (`report.email`)

Emails a usage or performance summary to approved recipient domains.

- **Safe to run again:** yes
- **Who can correct it:** Administrator
- **When it fails:**
  - 'No recipient is on an approved domain': add the domain to REPORT_ALLOWED_RECIPIENT_DOMAINS.
  - An email error: check the email integration under Admin, Integrations, Registry and run its connectivity test.

## Secret rotation check (`secrets.rotation_check`)

Raises an alert when a secret is older than the rotation interval.

- **Safe to run again:** yes
- **Who can correct it:** Security owner
- **When it fails:**
  - The run fails on purpose when a secret is overdue; its error lists which. Rotate the secret, then record the new date as NAME_ROTATED_AT.

## Interface check (`interface.check`)

Compares each live integration's response time and error rate with its thresholds and raises an interface.degraded event.

- **Safe to run again:** yes
- **Who can correct it:** Administrator
- **When it fails:**
  - A failed run means the check could not read the interface statistics. A slow or failing interface is delivered as an alert.

## Call-volume check (`business.volume_check`)

Compares this hour's call volume with the same hour in earlier weeks and raises a business.volume_dip event on a large fall.

- **Safe to run again:** yes
- **Who can correct it:** Service manager
- **When it fails:**
  - 'Baseline not ready' is normal for the first two weeks of live traffic; nothing is alerted until then.

## EMR write-back (queued) (`emr.writeback`)

Writes a completed note to the hospital record through the EMR integration.

- **Safe to run again:** yes
- **Who can correct it:** Administrator, EMR owner
- **When it fails:**
  - Check the EMR integration and its credentials under Admin, Integrations.
  - After four failures it moves to the dead-letter list; replay it once the EMR is reachable. The note stays safe in the encounter, and the nurse can copy it meanwhile.

## Email send (queued) (`email.send`)

Sends one queued email through the approved email service.

- **Safe to run again:** no, see below
- **Who can correct it:** Administrator
- **When it fails:**
  - Check the email service connection. Replay only if you are sure the first attempt did not deliver, as a replay can send the message twice.
